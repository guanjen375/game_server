# 遊戲伺服器（Tailscale 內網）

在自己的電腦上開一個網頁遊戲大廳，只有同一個 [Tailscale](https://tailscale.com/) 內網的裝置連得到。手機、平板、電腦用瀏覽器打開就能玩，不用安裝 App。

| 遊戲 | 網址 | 說明 |
| --- | --- | --- |
| 暗棋 | `/banqi` | 翻開棋子、以大吃小，不允許連吃 |
| 中國象棋 | `/xiangqi` | 標準規則，可悔棋、提示，也能兩人對下 |
| 黑白棋 | `/reversi` | 夾住對方的棋子就翻面，子多的獲勝；可悔棋、提示，也能兩人對下 |
| 台灣十六張麻將 | `/mahjong` | 花牌、吃碰槓、台數計算，和三家電腦對打 |
| 台灣麻將（自我模式） | `/mahjong-me` | 胡牌被胡限定個人（電腦不會自摸、也不會胡別家電腦的牌） |
| 拱豬 | `/gongzhu` | 四人撲克吃墩，避開豬（♠Q）、搶到羊（♦J） |
| 大老二 | `/bigtwo` | 四人撲克，♣3 開局，最先出完手牌的人獲勝 |
| 小丑牌：午夜劇場 | `/balatro` | 單人牌組構築，組合小丑、升級牌型，連闖八幕盲注 |

## 需求

- Linux 與 Python 3（只用標準函式庫，不用另外安裝套件）
- 拱豬的電腦要照模型出牌時，另外要 NumPy 和 C++ 編譯器（Ubuntu：`sudo apt install python3-numpy g++`）。沒裝的話其他都照常，拱豬的電腦用原本的打法。
- 已安裝並登入 Tailscale：`tailscale ip -4` 要能印出 100.x.x.x 的位址
- 瀏覽器能連到這台 Tailscale 伺服器即可。遊戲樣式、圖示與封面都由伺服器提供。

## 使用方式

```bash
python3 open_server.py            # 在背景開啟伺服器（關掉終端機、登出後仍會繼續執行）
python3 open_server.py status     # 查看狀態與網址
python3 open_server.py stop       # 關閉
python3 open_server.py restart    # 重新啟動
python3 open_server.py run        # 在前景執行（Ctrl+C 結束），除錯用
```

伺服器啟動時會自動抓這台的 Tailscale IP，只在這個位址上監聽（預設 port 8686），所以區網或外網都連不到，只有同一個 Tailscale 內網的裝置可以。啟動後會印出網址，用 Tailscale 內網的裝置打開 `http://<這台的 Tailscale IP>:8686/` 就是遊戲大廳。

- `--port 9000`：改用其他 port
- `--host <位址>`：改在其他位址監聽（例如 `127.0.0.1` 只給這台自己用）
- `--data-dir <資料夾>`：對局紀錄改存到別的資料夾（預設是專案裡的 `gaming_data/`，見下方「對局紀錄」）
- `--model-dir <資料夾>`：訓練好的模型改從別的資料夾讀（預設是專案裡的 `train_out/`，見下方「讓電腦照模型出牌」）

紀錄檔寫在 `server.log`。程式不會設定開機自動啟動，重新開機後要再執行一次。

iPhone／iPad 用 Safari 打開遊戲大廳，點「分享」→「加入主畫面」，就能像 App 一樣開啟；進入遊戲後點左上角的圖示可以回到大廳。

大廳可依棋類、麻將或撲克篩選遊戲。右上角可選七款主題，包括經典牌桌（預設）、紙上棋室、東京夜色、港灣晨霧、春日櫻花、琥珀茶室與石墨銀灰。各款遊戲共用同一個主題設定。對局中打開「選單」→「規則與設定」即可切換，瀏覽器會記住選擇。紙上棋室與東京夜色的配色分別參考 [Solarized](https://ethanschoonover.com/solarized/) 與 [Tokyo Night](https://github.com/tokyo-night/tokyo-night-vscode-theme)。

拱豬結算後，點計分板的「局後複盤」可看本局打法，以及哪些墩值得改出哪張牌、原因與推演分差。先顯示分差最大的三墩，其餘建議可展開。每個比較都從實戰當時的牌面出發，讓實出與改出的牌面對同樣深度的防守推演。先前的牌局可從「歷局得分紀錄」回看。

展開「查看四家手牌與完整推演」可看每一手的南家牌分與逐墩打法。對本局 BOT 沿用當墩實際的內建算法或模型版本與強弱設定，固定內建 BOT 的抽樣。對最佳防守則假設其餘三家都知道四手牌，聯手壓低南家的牌分。搜尋證實最佳值後會標上「已證最佳」。

小丑牌可從大廳「撲克」分類進入。選 1 至 5 張手牌即可預覽得分，過關後可買小丑、升級牌型或把銀箔牌加入牌組。在同一瀏覽器重開會接回原局，「牌型與設定」可查看各牌型的等級與底分。

## 對局紀錄

每一局都會自動記錄下來，不用按任何按鈕（之後分析打牌習慣、訓練電腦用）：

- 一局打完時存一次。打到一半關掉頁面、回大廳或按「重新開始」，打到一半的進度也會存下來。只是打開頁面、還沒出過牌（下過棋）的不記。
- 存在 `gaming_data/<遊戲>/<年-月>/<編號>.json`，一局一個檔；編號是開局時間加亂碼，例如 `gaming_data/mahjong/2026-11/20261120-164512-k3f9x2.json`。
- `gaming_data/` 列在 `.gitignore` 裡，不會進 git（裡面有連線裝置的 IP）；要備份就複製這個資料夾。
- 玩的時候連不上伺服器（Tailscale 斷線、伺服器重開）也不會漏：紀錄先留在瀏覽器裡，連得上時、或下次打開任何一個遊戲時補送。

小丑牌跨分頁或重開後續玩的紀錄保留整局種子與完整操作，可獨立重播。`actionOffset` 是本次續玩前已有的操作數。

每個檔的內容：

| 欄位 | 說明 |
| --- | --- |
| `game`、`id`、`status` | 哪個遊戲、這一局的編號、`finished`（打完）或 `unfinished`（沒打完） |
| `started`、`ended`、`saved` | 這一局開始、結束的時間（玩家裝置的時間），和伺服器存檔的時間 |
| `ip`、`ua` | 哪一台裝置玩的（Tailscale IP 和瀏覽器） |
| `session`、`seq` | 同一次打開頁面玩的各局 `session` 相同；`seq` 是這一局第幾次存檔（中途存過進度的會大於 1） |
| `build` | 遊戲檔的版本（git 的 blob 編號），用 `git log --all --find-object=<build>` 查得到是哪一次 commit 的檔案 |
| 其餘欄位 | 這一局的內容：第幾局、設定、各家是誰（`ai` 表示電腦）、發到的牌、依順序的每一手、結果 |

玩家按過「提示」才出的那一手會標 `hint`，麻將「自動胡牌」替玩家打的牌標 `auto`；悔掉的那幾手不會留在紀錄裡。電腦照模型出的牌標 `bot`（見下方「讓電腦照模型出牌」）。各遊戲的牌、棋子和座位怎麼編號，寫在各遊戲檔裡 `getRecord()` 上面的說明。

## 訓練模型

`train_gpu.py` 用 `gaming_data/` 的對局紀錄，訓練「照玩家的習慣出牌（下棋）」的模型，之後做自己的電腦對手用。要在有 NVIDIA GPU、裝了 [PyTorch](https://pytorch.org/get-started/locally/)（支援 CUDA 的版本）的電腦上執行；找不到 NVIDIA GPU 會直接顯示錯誤，不會改用 CPU。

```bash
python3 train_gpu.py gongzhu           # 用 gaming_data/gongzhu/ 的紀錄訓練，模型放在 train_out/gongzhu/
                                       # 訓練中：按 p 暫停／繼續，按 q 存檔後離開
python3 train_gpu.py gongzhu status    # 看練到哪裡
python3 train_gpu.py                   # 列出每個遊戲有幾局紀錄、練到哪裡
```

其他遊戲把 `gongzhu` 換成 `mahjong`、`bigtwo`……（就是 `gaming_data/` 底下的資料夾名稱）。在 Windows 上把開頭的 `python3` 換成 `python`。

- **暫停**都在訓練的那個視窗裡按鍵：
  - `p`：暫停。訓練把進度存好、把 GPU 完全讓出來，視窗停在暫停；再按一次 `p`（或 Enter）就從暫停的地方接著練。
  - `q`（或 Ctrl+C）：存檔後離開。之後再執行一次同一個指令，一樣從停下來的地方接著練。
  - 訓練途中 GPU 出錯也會停在暫停，GPU 可以用了再按 `p` 接著練。
  - 訓練途中每 60 秒會自動存檔（`--save-every` 可以改），被強制關掉或當機時，下次執行從最後一次存檔接著練。
- 建議開在 `tmux` 裡跑（`tmux new -s train`）：斷線了訓練還在，`tmux attach -t train` 回來一樣按 `p`、`q`。放在背景或排程執行、沒有視窗可以按鍵時，改用 `python3 train_gpu.py gongzhu pause`（或 Ctrl+C、kill）暫停。
- **學什麼**：把每一局重排一遍，在玩家每次要做決定的時候，記下他當時看得到的東西和他選了什麼，讓模型學著猜。只學真人的決定；電腦對手的、按過「提示」才做的、麻將自動胡牌替玩家打的都不學（`--players all`、`--with-hints` 可以改）。`--ip <來源 IP>` 只用某一台裝置玩的紀錄。
- **產出**在 `train_out/<遊戲>/`：`model.pt`（模型，驗證成績最好的那一輪）、`log.csv`（每一輪的成績）、`checkpoint.pt`（訓練進度，接著練用）、`status.json`（目前狀態）。
- **分享模型**：`model.pt` 和 `log.csv` 會進 git，練完 `git add train_out`、commit、push，別人拉下來就能用（用模型不需要 GPU，裝了 PyTorch 就行，讀法見 `train_gpu.py` 的 `load_model()`；遊戲伺服器用它出牌連 PyTorch 都不用，見下方「讓電腦照模型出牌」）。訓練進度、狀態這些只在訓練那台用的檔案列在 `.gitignore` 裡，不會進 git。
- 訓練完會顯示「沒練過的對局裡猜中玩家怎麼選的比例」，旁邊附上亂選的比例當對照。對局越多越準；只有幾十局時模型只能當參考。
- 之後多了新的對局，再執行一次就會用全部的紀錄重新訓練（上一個模型留成 `model.previous.pt`）；紀錄沒變的話不會重練，要重練加 `--restart`。
- 訓練的電腦和遊戲伺服器不是同一台時，把 `gaming_data/` 複製過去（它不在 git 裡），或用 `--data-dir` 指到紀錄的資料夾；`--out-dir` 可以改模型放哪裡。其他設定見 `python3 train_gpu.py --help`。

## 讓電腦照模型出牌

`train_out/<遊戲>/` 裡放著模型檔，遊戲裡就多了模型可以選：選了之後，電腦不用頁面內建的打法，改成每一手都問模型。伺服器這邊不需要 PyTorch，也不需要 GPU。目前接上的是拱豬（三家電腦用同一個模型）。

- 模型檔是 `model.pt`（`train_gpu.py` 練出來的就叫這個），或檔名帶名稱的 `model_<名稱>.pt`（例如 `model_20261123_b.pt`；名稱只用英文字母、數字、`_`、`-`）。一個遊戲可以放好幾個，每個都能選：名稱大的（日期新的）排前面，`model.pt` 排最後。
- 拱豬的模型出牌前會先往後推算（`gongzhu_search/`），伺服器要裝 NumPy 和 C++ 編譯器；第一次讀模型時會把推算的程式編譯好，放在 `~/.cache/gongzhu-search/`。`python3 open_server.py status` 的拱豬那幾行寫著「出牌前會先推算」，才表示伺服器真的在推算；沒寫的話是伺服器還在跑舊的程式，要 restart。

從訓練到用上：

```bash
# 訓練的那台：練完把模型推上去
python3 train_gpu.py gongzhu
git add train_out && git commit -m "Update the Gong Zhu model" && git push

# 遊戲伺服器這台：只換了模型檔的話，拉下來就生效，不用重開伺服器
git pull
python3 open_server.py restart    # 拉下來的有改到程式（.py 檔、gongzhu_search/）才需要
python3 open_server.py status     # 會列出現在哪些遊戲有模型可以選、是哪個模型
```

然後在遊戲裡選：**選單 → 規則與設定**和**選單 → 計分板**（每一局結算時會自動打開）裡都有「電腦的打法」，底下一行寫著選的那個模型（用幾局練的、什麼時候存檔、猜中的比例）。選了之後這台裝置會記住，其他裝置不受影響。大廳裡，有模型可以選的遊戲會標「可以和模型對打」。

選單上列哪幾個，由 `train_out/<遊戲>/choices.json` 設定：照檔案裡的順序列，`label` 是選單上的字，`play` 是誰出牌（`builtin` 是頁面內建的算法；`normal:<名稱>` 是 `model_<名稱>.pt` 照「正常」出牌，`weak:<名稱>` 是「較弱」）。拱豬現在列四個：

| 選單上的字 | 誰出牌 |
| --- | --- |
| 遊戲設定(65) | 頁面內建的算法（預設） |
| 模型A(100) | `20261123_b` 照「正常」出牌 |
| 模型B(100) | `20261123_a` 照「正常」出牌 |
| 舊模型(90) | `20261122` 照「正常」出牌 |

括號裡是強度（見下面「電腦的打法的強度」），寫在 `label` 裡，重量之後要自己改。模型檔不在了的那一項不列。沒有 `choices.json` 的遊戲，選單是原本的電腦加上每個模型的兩種打法：

- **模型 <名稱>・正常**：完全照模型，每一手都出模型分數最高的那一張。`model.pt` 沒有名稱，就是「模型・正常」。
- **模型 <名稱>・較弱**：一樣照模型，但照它估的機率抽一張，所以有時會出它的第二、第三選擇。模型估的機率不到一成的牌不出；同一個局面每次出的都一樣（悔牌重來不會換一張）。要更弱或沒那麼弱，改 `model_bot.py` 開頭的 `WEAK_FLOOR`、`WEAK_TEMPERATURE`（旁邊有各種設定量出來的差距），改完重開伺服器。
- 量過強度的，選項後面寫「（強度 N）」：最強的是 100，每少 1，和同樣的對手打平均每局少拿 1 分。

其他：

- 模型不一定比原本的電腦強：`train_gpu.py` 練的是「學玩家的出牌習慣」的模型，對局少的時候通常比較弱，所以預設還是原本的電腦。拱豬現在放的三個是另外用自我對打練的，都比原本的電腦強（見下面）。
- 模型檔換了不用重開伺服器，玩的人也不用重新整理頁面：下一局開始就用新的。
- 選了模型，但沒有模型檔、模型和現在的程式對不上（看牌的欄位改過，要重新訓練）、伺服器沒裝 NumPy 或 C++ 編譯器、或玩的時候連不上伺服器，電腦就用原本的打法照常出牌，「電腦的打法」底下會寫原因。「出牌提示」一直是內建的算法，和模型無關。
- 對局紀錄裡，模型出的牌標 `bot`（值是當時的打法 `normal` 或 `weak`），那一局另外有 `model`：模型檔的 git blob 編號，`git log --all --find-object=<model>` 查得到是哪一次 commit 的模型。沒標的是內建電腦出的。訓練只學真人的決定，這些標記不影響訓練。

### 拱豬的三個模型

`train_out/gongzhu/` 裡有三個模型，都是在 H200 那台用自己和自己對打練的（不是學玩家的紀錄）。沒有特別選的時候用 20261123_b。

| 名稱（檔案是 `model_<名稱>.pt`） | 說明 | git blob 編號（對局紀錄的 `model`） |
| --- | --- | --- |
| `20261123_b` | 2026-11-23 從 20261123_a 接著練的，出牌前會先推算。最強 | `5ddd327da167e80a5c0a3653eb1cf7992253f6f8` |
| `20261123_a` | 2026-11-23 從 20261122 接著練的，出牌前會先推算 | `465e1ccc6374cd143396f863cc52c7d95483fbdd` |
| `20261122` | 2026-11-22 練的第一版，出牌時不推算 | `e9e87aaf87953dbb5ce7285c711b0e2b726f85fc` |

訓練那邊的檔名依序是 `20261123_b_model.pt`、`20261123_a_model.pt`、`generation-7_20261122-161404.pt`。

- **出牌前的推算**（20261123_a、20261123_b）：有兩張以上能出時，照自己的手牌和桌上看得到的牌，抽 48 種另外三家可能拿的牌，每張能出的牌都往後推 8 手、最後兩墩算到底，選平均分差最好的那張。只用輪到的那一家看得到的東西。只接個人設定的規則（`player_special`），其他規則的牌局電腦用原本的打法。
- **強度**：兩邊直接對打，每副牌讓少的那一方輪流坐四個座位；數字是前面那一個每局平均多幾分（一家對三家／三家對一家）：
  - 20261123_b 對 20261123_a：+2.2／+2.8（訓練那邊量的，16,384 副牌），兩個差不多強。
  - 20261123_a 對 20261122：+18.1／+15.2（訓練那邊量的，4,096 副牌）。
  - 20261123_b 對 20261122：+15.5／+14.4（訓練那邊量的，4,096 副牌）；用遊戲伺服器實際的出牌程式另外量的是 +16.5／+11.6（2,048 副牌）。
  - 對原本的電腦（每一手都讓它算滿 400 次）：20261123_b 是 +29.2／+44.5（256 副牌）；20261122 一家對三家是 +20.3（7,168 副牌）。
- **速度**：會推算的兩個在 H200 那台（60 核心）出一張牌中位數 0.02 秒、最慢約 0.12 秒，機器被別的程式佔滿時最慢約 0.5 秒（遊戲頁面最多等 2.5 秒）；20261122 約 0.04～0.07 秒。
- **加新版本**：新練出來的模型放成 `model_<日期>.pt`，遊戲裡就多兩個選項。它的名稱最大，會排第一個、變成沒特別選時用的那一個，所以先和 20261123_b 直接對打，一家新對三家舊、三家新對一家舊兩種都要每局平均贏超過 10 分才放進來；放進來之後重量一次強度（見下面），這一段的表格和成績跟著改。
- `python3 train_gpu.py gongzhu` 練的是「學玩家出牌」的模型，會放成 `train_out/gongzhu/model.pt`，在遊戲裡是「模型・正常」「模型・較弱」，排在三個有名稱的模型後面。

### 電腦的打法的強度

強度是讓原本的電腦和三個模型的兩種打法，共七種，實際對打量的：每次挑四種同桌，35 種同桌組合各打 64 副牌，每副牌讓這四種輪流坐四個座位，共 8,960 局（2026-11-24 量的）。每種打法算出「和同一桌比，平均每局多拿幾分」，最強的是 100，每少 1，和同樣的對手打平均每局少拿 1 分。原本的電腦每一手都讓它算滿 400 次。

| 打法 | 強度 | 重抽牌時 95% 落在 |
| --- | --- | --- |
| 原本的電腦 | 65 | 60～69 |
| 模型 20261123_b・正常 | 100 | 94～100 |
| 模型 20261123_b・較弱 | 99 | 94～100 |
| 模型 20261123_a・正常 | 99 | 94～100 |
| 模型 20261123_a・較弱 | 100 | 95～100 |
| 模型 20261122・正常 | 88 | 83～91 |
| 模型 20261122・較弱 | 43 | 36～46 |

- 會推算的兩個模型，四個選項差不到誤差：「較弱」大約三成的牌和「正常」出得不一樣，但換出去的都是推算起來差不多好的牌，所以沒有變弱。20261122 不推算，「較弱」就真的弱很多。
- 選單上的數字是照這張表寫的（`choices.json` 的 `label`）：模型B 和舊模型量到的是 99 和 88，寫成 100 和 90。
- 重量：在專案根目錄執行 `node tests/gongzhu/strength.cjs`（60 核心約 11 分鐘），它會在 127.0.0.1 自己開模型伺服器來對打，量完寫進 `train_out/gongzhu/strength.json`（伺服器讀這個檔），每一局的結果寫進 `reports/gongzhu/strength-games.jsonl.gz`。量法寫在那個檔的開頭。
- 沒有 `choices.json` 的時候，選項後面的強度是從 `strength.json` 讀的；量的時候的模型檔換過、多了或少了一個，強度就對不上了，先不顯示，重量一次就有。

## 新增遊戲

現有遊戲的共用介面與圖片放在 `games/assets/`。直接在瀏覽器開啟遊戲 HTML 時，把這個資料夾放在 HTML 旁邊即可。六款沿用 Tailwind 工具類別的遊戲使用已編譯的 `layout.css`。若新增工具類別，可在專案根目錄執行 `npx --yes tailwindcss@3.4.17 --content './games/*.html' --output games/assets/layout.css --minify` 更新。

把單一檔案的網頁遊戲放進 `games/`，檔名就是網址：`games/foo.html` 對應 `http://<IP>:8686/foo`，不用重開伺服器。沒有登記在 `open_server.py` 的 `CATALOG` 裡的遊戲，會用網頁標題列在大廳的「其他」；想指定名稱、分類、圖示和說明，就在 `CATALOG` 加一筆。將同名的 WebP 圖片放進 `games/assets/`，即可在遊戲卡片顯示封面。

新遊戲要自動記錄，得自己交出紀錄：伺服器會在每個遊戲頁面放一個 `window.GameRecorder`，每一局開始時呼叫 `GameRecorder.begin(fn)`（`fn()` 回傳這一局目前的紀錄，打完時帶 `finished: true`；還沒有值得記的內容時回傳 `null`），一局結束、或還沒打完就要換掉這一局之前呼叫 `GameRecorder.end()`。現有七個遊戲的 `getRecord()`、`recordBegin()`、`recordEnd()` 可以照著寫。要讓 `train_gpu.py` 也能拿新遊戲的紀錄訓練，還要在 `train_gpu.py` 裡替它寫一個 `Game`（怎麼把一局紀錄重排成一個一個的決定），現有七個遊戲的可以參考。

要讓一個遊戲的電腦可以照模型出牌（目前只有拱豬接上），兩邊各加一小段：`train_gpu.py` 那個遊戲的 `Game` 加 `upcoming()`（從這一局到目前為止的紀錄，算出輪到的人看到什麼）；遊戲頁面加一個讓玩家選「電腦的打法」的地方，每一局開始時呼叫 `GameBot.refresh()`，玩家選了模型的話，輪到電腦時呼叫 `GameBot.choose(這一局到目前為止的紀錄, 座位, 打法)`，拿到的是模型選的那一手，拿到 `null`（沒有模型、連不上）就用自己原本的電腦。`GameBot` 是伺服器加在頁面上的（`open_server.py` 的 `BOT`），拱豬的 `executeAITurn()`、`setBotMode()` 可以照著寫。
